--- Known gaps / needs verification (GUI restoration + TUI Omarchy theming session) ---

Known gaps (left as-is on purpose):
- TUI has no screens yet for backup/restore/password rotation. The shared
  logic already lives in journal_core.py (create_journal_backup,
  list_journal_backups, validate_backup_file, rotate_journal_password,
  log_password_rotation_failures), ready for the TUI to build on.
- Tk 9 treeview bug: leaf-row (dated entry) tree items show a disclosure
  triangle they shouldn't have. Confirmed Tk-9-specific (does not
  reproduce under Tk 8.6) - a Tk 9 regression in the vendored Azure ttk
  theme's image-based indicator, not our code. Workaround: run the GUI
  with a Tk 8.6 Python (e.g. system python3) instead of a Tk 9.0.4 one
  (e.g. a uv-managed venv's bundled Python). apply_omarchy_colors's
  button/scrollbar/treeview-heading recoloring is also gated off on Tk 9
  for the same family of image-rendering issues
  (_tk_supports_image_style_overrides in secure_journal.py).
- Failed-attempt lockout (5 wrong passwords) is implemented independently
  in both frontends (SecureJournalApp.max_attempts in secure_journal.py,
  UnlockScreen.MAX_FAILED_ATTEMPTS in journal_tui.py) - not shared via
  journal_core.py. Possible future unification.
- [FIXED] journal_core.create_journal_backup's timestamp suffix used to
  have 1-second granularity ("%Y%m%d-%H%M%S"), so two backups created
  within the same wall-clock second would collide on filename and
  silently overwrite each other instead of both existing. Now includes
  microseconds ("%Y%m%d-%H%M%S-%f"), so this no longer happens.
  scripts/smoke_test.py's time.sleep(1.1) workaround for this (with a
  comment referencing it) is now unnecessary but harmless - left as-is
  since that file must keep passing unmodified.
